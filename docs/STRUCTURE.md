# Структура каталога `docs/`

Шпаргалка: **где лежит что** и **куда класть новый файл**. Подробные описания разделов — в [README.md](README.md).

---

## Дерево папок

```
docs/
├── STRUCTURE.md          ← этот файл (карта + правила)
├── README.md             ← расшифровка разделов и списки ключевых документов
│
├── reference/            ← канон: термины, хроника крупных изменений
├── platform/             ← архитектура платформы, SaaS, омниканал, окружения
├── features/             ← RFC и продуктовые спеки по фичам (витрина, legal, …)
├── payments/             ← эквайринг заказов, платёжные долги/TODO
├── backlog/              ← планы и оптимизации до реализации (не «источник правды» кода)
├── runbooks/             ← деплой, серверы, Telegram relay, self-hosted Supabase
├── integrations/       ← внешние API, контракты, планы интеграций
├── verticals/
│   └── festival/         ← только фестивальная вертикаль
├── content/
│   ├── brainstorm/       ← идеи, стратегия, рилсы, черновики (может устаревать)
│   └── instagram-carousels/
├── marketing/            ← лендинги, партнёрские структуры страниц
└── meta/                 ← GSD, UI-гайды процесса (не продукт)
```

---

## Куда класть новый файл

| Если это… | Папка |
|-----------|--------|
| Словарь терминов, крупный «что изменилось в продукте» | `reference/` |
| Мультитенант, биллинг платформы, модули/цены, омниканал, Vercel/Supabase | `platform/` |
| Спека или RFC по одной фиче (витрина, checkout, cookie/ПДн, отзывы…) | `features/` |
| YooKassa/Т-Банк, webhooks заказов, открытые платёжные задачи | `payments/` |
| План работ / оптимизация / «сделать потом», чеклисты | `backlog/` |
| Пошаговая инструкция для ops (деплой, SSH, relay) | `runbooks/` |
| Контракт или план по внешней системе (iiko, QuickResto, VK…) | `integrations/` |
| Только сценарий фестиваля | `verticals/festival/` |
| Мозговой штурм, сценарии рилсов, стратегия без фиксации в коде | `content/brainstorm/` |
| Тексты каруселей / публичные тезисы | `content/instagram-carousels/` |
| Структура лендинга, A/B варианты блоков для партнёров | `marketing/` |
| Как мы работаем (GSD, UI skill), не домен продукта | `meta/` |

---

## Быстрое решение: `backlog/` vs `features/` vs `platform/`

- **`backlog/`** — «как сделаем / что оптимизируем», часто с чекбоксами и ссылками на код; не обязано отражать текущее поведение.
- **`features/`** — продукт + техника по **конкретной фиче**; после релиза сверять с кодом, при необходимости дописать строку в `reference/RECENT_MAJOR_CHANGES_RU.md`.
- **`platform/`** — сквозные правила и модель (тенанты, города, биллинг платформы, омниканал), на что опираются несколько фич.

---

## Имена файлов (кратко)

- Канонические продуктовые доки на русском часто в формате **`TOPIC_DETAIL_RU.md`** (как в `platform/`, `payments/`, `features/`).
- В `content/brainstorm/` допустимы свободные названия и подпапки (`reels/`, `карусели/`).

---

## Устаревание

`content/brainstorm/` и черновики в `features/` — снимок на момент написания. **Источник правды по факту поведения** — код и тесты; зафиксированный релиз — в `reference/RECENT_MAJOR_CHANGES_RU.md`.
