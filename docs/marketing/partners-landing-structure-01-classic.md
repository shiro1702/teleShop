# Лендинг партнеров — вариант 1 (классический: "сайт под ключ, но как платформа")

## Для чего этот вариант
Подходит для первого знакомства, когда нужно объяснить, что вы продаете не шаблонный сайт, а развивающуюся экосистему для доставки и QR-меню.

## Логика блоков (сверху вниз)

### 1) Hero: новый уровень вместо "сайта-визитки"
- Заголовок: `Не просто сайт под ключ. Платформа продаж и доставки для ресторанов`
- Подзаголовок: `Единое пространство: сайт + миниаппы в мессенджерах + общий канал горячих лидов`
- CTA: `Запустить платформу для ресторана`
- Вторичная кнопка: `Посмотреть демо экосистемы`

### 2) Что это за продукт (простыми словами)
- Pocket Menu — это экосистема для заведений, где ресторан получает:
  - современный сайт по подписке;
  - QR-меню и заказы из зала;
  - заказы в Telegram/миниаппах;
  - инструменты удержания гостей (бонусы, промокоды, рассылки, сторис).
- Визуал: `Клиент -> сайт / QR / Telegram mini app -> единый движок ресторана`.

### 3) Почему обычный "сайт под ключ" уже не работает
- Шаблонный сайт быстро устаревает и не помогает с повторными продажами.
- Нет единой клиентской базы, поэтому маркетинг работает вслепую.
- Нет развития функционала под рынок (доставка, лояльность, автоматизация).
- Вывод: ресторану нужна не "страница", а живая платформа с модулями.

### 4) Ключевая ценность экосистемы для партнеров
- Приток горячих лидов из общего канала агрегатора.
- Омниканальность: сайт + mini app в мессенджерах + QR-точки в зале.
- Удобство для клиента: быстрый заказ, повтор заказа, промо-механики.
- Удобство для ресторана: единая операционная логика и рост LTV.

### 5) Что получает ресторан в базе (быстрый старт)
- `core_qr_menu` — QR-меню в заведении.
- `core_telegram_orders` — поток заказов/уведомлений в Telegram.
- Позиционирование блока: `Запускаемся быстро, затем растем по модулям`.

> Примечание для страницы: функционал подключается тумблерами. Ресторан платит только за нужные модули.

### 7) Блок "Маркетинг, который возвращает гостей"
- Рассылки в мессенджерах по базе гостей.
- Сегменты и триггеры (день рождения, гео, реактивация).
- Бонусная система, промокоды, акции.
- Формат сторис и контентные промо внутри экосистемы.

### 8) Блок "Кросс-партнерка внутри экосистемы"
- Рестораны, кафе, бары, киоски обмениваются аудиторией через совместные офферы.
- Механика: пользователь заказывает в одном месте и видит релевантные предложения соседних партнеров.
- Ценность: рост заказов без покупки холодного трафика.

### 9) Как происходит запуск
- Шаг 1: аудит текущих каналов и модели доставки.
- Шаг 2: запуск сайта + QR + мессенджерного канала.
- Шаг 3: подключение модулей роста по задачам бизнеса.
- Шаг 4: сопровождение и развитие платформы по roadmap.

### 9.1) Калькулятор для партнеров (на странице)
- База: `1200 ₽/мес` (включает 1 филиал).
- Каждый дополнительный филиал: `+500 ₽/мес`.
- Форматы работы: доставка (`+2200 ₽`), самовывоз (`+800 ₽`), заказы в зале (`+0 ₽`).
- Модули в калькуляторе: CRM (`+1200 ₽`), лояльность (`+900 ₽`), онлайн-оплата (`+480 ₽`), отзывы (`+700 ₽`).
- Формула: `итог = база + форматы + доп. филиалы + модули`.

### 9.2) Примеры подключения с расчетом
- `Доставка + самовывоз` (2 филиала, CRM, лояльность, онлайн-оплата): `7 180 ₽/мес`.
- `Бар с кнопками заказа` (1 филиал, зал/QR, модуль отзывов): `1 900 ₽/мес`.
- `Киоск с едой` (1 филиал, самовывоз, CRM, онлайн-оплата): `3 680 ₽/мес`.

### 10) Финальный CTA
- Заголовок: `Подключите экосистему, которая растет вместе с вашим рестораном`
- Кнопка: `Получить персональную сборку модулей`
- Дополнительно: `Запросить демо с расчетом окупаемости`.

## Почему этот вариант работает
- Четко разводит понятия "шаблонный сайт" и "развивающаяся платформа".
- Дает понятный переход: бесплатное ядро -> платные модули роста.
- Показывает не только функционал, но и канал привлечения горячих лидов.
